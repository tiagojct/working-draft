# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A [Quarto](https://quarto.org/) book — *The Working Draft: Writing and Data Visualisation for Health Researchers* by Tiago Jacinto (FMUP). Three parts: Part I on scientific writing, Part II on data visualisation, Part III on reproducible research (a TRIPOD+AI prediction-model chapter and a reproducibility/code-as-output chapter). Two appendices follow the conclusion: a [glossary](chapters/glossary.qmd) and reusable [checklists](chapters/checklists.qmd). The audience is three overlapping groups — clinical-research PhDs, health-data-science PhDs, and medical undergraduates. There is no application code — the source is `.qmd` (Quarto Markdown) chapters, Python figure scripts, and a custom SCSS theme.

## Commands

```bash
quarto preview                       # live-reload local server (use while editing)
quarto render                        # full book build (HTML + PDF) → _book/
quarto render --to typst             # PDF only (Typst) → _book/The-Working-Draft.pdf
quarto render chapters/03-clear-writing.qmd   # render a single chapter (faster iteration)
python3 scripts/check-refs.py        # integrity lint (CI gate) — see below for what it catches
python3 scripts/check-numbers.py     # cohort lint (CI gate): prose descriptives vs the committed CSVs
pip install -r figures/requirements.txt       # deps for every script below
python3 figures/sw_cohort.py         # regenerate figures/sw/cohort.csv (heart failure)
python3 figures/dv_cohort.py         # regenerate figures/dataviz/cohort.csv (hypertension) — see caveat below
python3 figures/generate.py          # regenerate every PNG under figures/sw/ and figures/dataviz/
python3 figures/meta_forest.py       # regenerate figures/sw/forest-meta.png (meta-analysis forest)
python3 figures/predmodel.py         # regenerate figures/sw/predmodel-{roc,calibration,dca}.png (Part III)
python3 figures/social_card.py       # regenerate assets/social-card.png (Open Graph card)
```

[.github/workflows/deploy.yml](.github/workflows/deploy.yml) builds and deploys to GitHub Pages on push to `main`; it runs [scripts/check-refs.py](scripts/check-refs.py) before rendering. [.github/workflows/check.yml](.github/workflows/check.yml) runs on every pull request: `check-refs.py` first, then a full `quarto render` (both HTML and Typst — checking only HTML would let PDF-only breakage such as a duplicate bib key reach `main`), then a non-blocking lychee external-link check, then uploads `_book/` as an artifact.

`check-refs.py` exists because `quarto render` exits 0 on every one of these. It fails the build on: an undefined citation key; a bib key defined twice (silent in HTML, fatal in Typst); a cross-reference (`@fig-`, `@sec-`, `@tbl-`, `@eq-`) with no matching label; a missing image or `_quarto.yml` asset path; an internal `.qmd` link whose file or `#anchor` does not exist; a chapter file missing from the `_quarto.yml` list (it would render nowhere); and an image with neither alt text nor `fig-alt`. It warns, without failing, about figure files nothing references and labels nothing cites.

`check-numbers.py` guards the other silent failure: prose drifting away from the committed cohorts. It recomputes the cohort sizes, group sizes, missingness, and readmission rate from the CSVs and fails if a chapter quotes a superseded value or an arm-size run that no longer matches. Regression estimates are not covered — `figures/predmodel.py` and `figures/meta_forest.py` print theirs on every run, and every estimate quoted in Part I and Part III is fitted on the committed draw rather than assumed.

## Architecture

- **[_quarto.yml](_quarto.yml) is the source of truth for chapter order and TOC.** The numeric prefix on `chapters/NN-*.qmd` is a convenience; Quarto does not infer order from the filename. A new chapter is invisible until it is added to the `book.chapters:` list in `_quarto.yml`. Unprefixed files (e.g. `ai-writing.qmd`, `statistical-writing.qmd`, `part-ii-bridge.qmd`, `guide.qmd`) are interlude/bridge chapters interleaved between the numbered ones — check `_quarto.yml` to see where each one slots in.
- **Two bibliographies.** [assets/refs-sw.bib](assets/refs-sw.bib) backs Part I (writing), [assets/refs-dataviz.bib](assets/refs-dataviz.bib) backs Part II (figures). Citations use Nature style via [assets/nature.csl](assets/nature.csl). When adding a citation, put the entry in the bib file that matches the part the chapter belongs to. Keys must be unique across the two files: pandoc/HTML dedupes silently, but the Typst PDF build fails hard on a duplicate key (a key cited from either part resolves book-wide, so define it once).
- **Margin references.** `reference-location: margin` plus the custom 780px body / 260px margin grid means citations and footnotes render in the right margin. Long content in margin notes will overflow — keep margin material short.
- **Theme is [Glauca](https://github.com/tiagojct/glauca)**, a light-first design system: IBM Plex Serif headings, IBM Plex Sans body, IBM Plex Mono code, one sky-blue mark (`#007AFF`) on a pale frost ground. Vendored into [assets/](assets/): `glauca.scss` (light/Pruina), `glauca-dark.scss` (dark/Profundum), `glauca.theme` (code highlight), `glauca-typst.typ` (PDF brand). [assets/book.scss](assets/book.scss) is the book-only layer — chiefly the type-forward landing hero, scoped to the index page via a hidden `.landing` marker and `main:has(.landing)` so chapters keep plain Glauca titles. Fonts are self-hosted: base64-inlined variable woff2 in [assets/glauca-fonts.css](assets/glauca-fonts.css) for HTML, and static IBM Plex TTFs under [fonts/glauca/](fonts/glauca/) (instantiated from the variable sources, since Typst 0.14 cannot use variable fonts) via `font-paths` for the PDF. Open Graph tags come from Quarto's built-in `open-graph`. The book renders with plain Quarto `html` + `typst` formats (no custom extension of its own).
- **The PDF is a Typst book, and Quarto builds it through the bundled `orange-book` extension.** That extension lives in the Quarto install (`/Applications/quarto/share/extension-subtrees/orange-book/`), not in this repo, and it decides the cover, the chapter title blocks, the running heads, and the page geometry. Three files bend it back to Glauca, and each carries the reason in its own header comment:
  - [assets/book-typst.typ](assets/book-typst.typ) — second `include-in-header` file, after the vendored Glauca one. Holds the palette constants, the figure-caption rule, and the `wd-cover` / `wd-colophon` builders. **Does not** set body `leading`: orange-book calls `set par(leading: 0.5em)` inside `book()`, which is nested deeper and wins, so the override sits at the end of the typst-show partial instead.
  - [assets/typst-partials/typst-show.typ](assets/typst-partials/typst-show.typ) — replaces orange-book's partial of the same name. Paints the cover into page 1's **foreground** (orange-book draws its own title band on top of anything passed to `cover:`, so the cover cannot be layered underneath), passes `wd-colophon` as `copyright:`, forces Glauca blue as `main-color`, and re-enables page numbering and body leading at the top of the body scope. Keep its marginalia block in sync with upstream.
  - [assets/typst-partials/page.typ](assets/typst-partials/page.typ) — replaces the upstream partial only to set `numbering: none`, so cover, credits, and contents run unnumbered.
- **Typst page geometry is derived, not declared.** Because chapters use `.column-margin`, Quarto routes the book through the `marginalia` package and computes the geometry itself in `meta.lua`, reading `margin.x` as *inner.separation* and *outer.far*. Left alone that produced a 76 mm body on a 210 mm page. The explicit `margin-geometry` block in `_quarto.yml` overrides all six values (25 mm inner + 120 mm body + 65 mm outer) and **must keep summing to the page width**; `margin:` there carries only `top`/`bottom`.
- **The site is published at `workingdraft.tiagojacinto.eu`.** The custom domain comes from the [CNAME](CNAME) file, which is listed under `project: resources:` so it lands inside `_book` (the artifact `actions/deploy-pages` uploads) rather than being set in the repository's Pages settings. DNS is a `CNAME` record for `workingdraft` pointing at `tiagojct.github.io`, unproxied. `site-url` makes Open Graph tags absolute; `open-graph: image:` is itself an absolute URL because Quarto otherwise resolves it per page and hands chapters a broken `/chapters/assets/…` path, and it must point at a real file because the fallback is Quarto's own inline link-icon data URI.
- **Licence and citation metadata.** The book is CC BY-NC-SA 4.0 ([LICENSE](LICENSE)); vendored IBM Plex (OFL 1.1) and `nature.csl` (CC BY-SA 3.0) are excluded there. [CITATION.cff](CITATION.cff) drives GitHub's "Cite this repository" box; [.zenodo.json](.zenodo.json) drives the Zenodo record on release and **overrides CITATION.cff entirely** when both are present, so change them together. Once a DOI is minted, set `wd-doi` in [assets/book-typst.typ](assets/book-typst.typ) and it appears on the credits page.
- **Figures are pre-rendered PNGs, not generated at render time.** Chapters reference files in `figures/sw/` (Part I) and `figures/dataviz/` (Part II) that are committed to the repo. To change a figure, edit and rerun [figures/generate.py](figures/generate.py), then commit the regenerated PNG(s). All figures are styled with Glauca (IBM Plex, pale/white ground, Okabe-Ito categorical, `glauca_seq` sequential ramp); no pequod, no FMUP.
- **`figures/generate.py` is self-contained** — it has no external repo dependency. It imports the vendored [figures/glauca.py](figures/glauca.py) purely for the side effect of registering the `glauca_seq`/`glauca_div` colourmaps, then applies its own `GLAUCA_RC` dict per figure; it does **not** call `use_glauca()` or load [figures/glauca.mplstyle](figures/glauca.mplstyle), so the palette constants are duplicated between the two files and must be changed in both. It registers the static IBM Plex faces from [fonts/glauca/](fonts/glauca/) so text renders correctly even where IBM Plex is not system-installed. [figures/meta_forest.py](figures/meta_forest.py) (systematic-reviews forest plot) and [figures/predmodel.py](figures/predmodel.py) (Part III ROC/calibration/decision-curve, fit on the committed Part I cohort) use the same styling; both are deterministic and print the numbers quoted in their chapters. The R plot examples in ch. 11/12/14 use the vendored [figures/glauca.R](figures/glauca.R) (`theme_glauca()`, `scale_*_glauca_*()`).
- **Simulated cohorts are part of the book's didactic conceit.** Part I uses a fictional heart failure / NT-proBNP cohort generated by [figures/sw_cohort.py](figures/sw_cohort.py) → `figures/sw/cohort.csv`; Part II uses a fictional hypertension cohort generated by [figures/dv_cohort.py](figures/dv_cohort.py) → `figures/dataviz/cohort.csv`. Both scripts are deterministic for a fixed `SEED = 20260515`, but the `numpy.random.default_rng` stream and pandas' CSV float formatting drift across major versions, so a fresh run under a different environment shifts the descriptive counts by a handful of patients. The committed `figures/sw/cohort.csv` was generated with numpy 2.4.6 / pandas 3.0.3, and the Part I prose descriptives (readmission 12.8 %, NT-proBNP available 5,065/5,204, BNP subset 2,068) track that draw — reconcile prose and CSV together if you regenerate. Both CSVs are now the current output of their scripts: `dv_cohort.py` was realigned (simple randomisation, so arms are unequal at 156/134/156/154; `follow_up_months` 3–24; `delta_*` as baseline minus six months, positive = reduction; `bp_class_6m` labelled `Pre-hypertension`) and `figures/dataviz/cohort.csv` regenerated from it, with every Part II figure and quoted number reconciled. Regenerating either CSV still shifts the descriptives, so if you re-run one, re-run `generate.py` and reconcile the prose in the same commit. They are intentionally simulated for the worked examples — do not treat them as real data or suggest replacing them with a real dataset.

## Editorial conventions

- The author's voice is deliberate: terse, opinionated, second-person where it earns it. Resist softening edits ("it might be worth considering…", "in some cases…") and resist boilerplate transitions. When in doubt, match the tone of [chapters/01-why-writing.qmd](chapters/01-why-writing.qmd).
- Several recent commits (`Detrope pass`, `Address SWOT findings`) explicitly removed AI writing tropes and tightened citations — keep that in mind before adding hedges, em-dash flourishes, or "it's not just X, it's Y" constructions.
- Repo URL and `repo-actions: [edit, issue]` are wired up — chapter pages have working "Edit this page" links pointing at GitHub.
